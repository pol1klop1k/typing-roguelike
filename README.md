# SIGNAL

Роглайт про скоростную печать, вдохновлённый Balatro.
Прототип: одно прохождение, выбор одного из трёх текстов.

## Запуск

### Что нужно

**[Node.js](https://nodejs.org/) версии 22.12 или новее** и npm 7+ (идёт в комплекте
с Node). Версия важна: Vite 8 требует Node 20.19+, а Vitest 5 уже 22.12+.
На Node постарше установка остановится с понятной ошибкой, а не сломается позже.

```bash
node -v    # должно быть v22.12.0 или выше
npm -v
```

### Первый запуск

```bash
git clone git@github.com:pol1klop1k/typing-roguelike.git
cd typing-roguelike
npm ci
npm run dev
```

Для клонированного репозитория используй именно `npm ci`, а не `npm install`.
`npm ci` ставит зависимости ровно по `package-lock.json` и предварительно
очищает `node_modules`. В этом проекте четыре пакета с нативными
бинарниками под конкретную платформу (Rolldown внутри Vite, движок
Tailwind, lightningcss и компилятор TypeScript), и `npm install` поверх
чужого состояния умеет их пропускать.

В терминале появится строка вида `Local: http://localhost:5173/`.
Открой этот адрес в браузере — игра запустится сразу, никакой сборки
и настройки не требуется.

Остановить сервер: `Ctrl + C` в терминале.

### Остальные команды

```bash
npm run test         # тесты игрового ядра, один прогон
npm run test:watch   # тесты в режиме наблюдения, перезапускаются при правках
npm run build        # production-сборка в папку dist
npm run preview      # локальный просмотр собранной версии
```

### Если что-то пошло не так

- **Порт занят.** Vite сам возьмёт следующий свободный порт и напишет его
  в терминале. Можно задать порт явно: `npm run dev -- --port 5180`.
- **`Cannot find native binding`.** Классический
  [баг npm с optional-зависимостями](https://github.com/npm/cli/issues/4828):
  платформенный бинарник не поставился. Лечится чистой переустановкой:

  ```bash
  rm -rf node_modules          # PowerShell: Remove-Item -Recurse -Force node_modules
  npm ci
  ```

  Если не помогло — удали заодно `package-lock.json` и выполни `npm install`.
  Лок-файл после этого пересоберётся, и его изменение нужно закоммитить.
- **`EBADENGINE` или отказ установки.** Версия Node ниже 22.12. Обнови Node,
  понижать требование в `package.json` не нужно.
- **Ошибки после обновления зависимостей.** Та же чистая переустановка:
  `rm -rf node_modules`, затем `npm ci`.
- **Игра не реагирует на клавиши.** Кликни один раз по странице: браузер
  не отдаёт фокус и не разрешает звук до первого действия мышью или клавишей.
- **Все нажатия идут в ошибки.** Проверь раскладку клавиатуры. Игра это
  распознаёт, не штрафует и показывает подсказку, но переключить раскладку
  нужно вручную.

## Как играть

Меню -> забег из 12 узлов -> отсчёт 3-2-1 -> печатай.

Забег идёт подряд: узел, склад, следующий узел. Провал любого узла
заканчивает забег целиком: предметы и кредиты теряются, следующий забег
начинается с пустыми руками.

Узлы каждый раз разные. Забег тянет двенадцать случайных фрагментов лора
из запаса в двадцать четыре и показывает их по возрастанию номера журнала:
набор всегда новый, но история всегда идёт вперёд, а не скачет.

- Каждый верный знак копит **символы**.
- В конце слова символы превращаются в очки: `символы x множитель`.
- Чистое слово повышает множитель на 0.2.
- Ошибка снимает 0.6 множителя и отнимает время. Каждая следующая ошибка
  дороже предыдущей: 1, 2, 3 секунды, дальше по 3. Ниже x1 множитель
  не опускается.
- Победа наступает в момент набора цели, даже если текст не дописан.
- Поражение: кончилось время либо кончился текст, а цели нет.
- За взятый узел дают кредиты. Поздние узлы платят больше.

Ввод блокирующий: пока не нажата верная клавиша, курсор не двигается.
Backspace не нужен, ошибок в тексте не остаётся.

### Окно безопасности

Ошибка открывает окно на 0.5 секунды. Промахи внутри окна не стоят ничего:
ни времени, ни множителя, ни строчки в счётчике ошибок. Окно закрывается
досрочно, как только нажат верный символ.

Это не поблажка, а поправка на физиологию: человек печатает пакетами и,
осознав промах, по инерции успевает добить ещё символ-другой. Наказывать
за них означало бы наказывать за скорость реакции, а не за навык.

Промах внутри окна подсвечивается жёлтым, настоящая ошибка - красным.

### Обратная связь по очкам

Очки за слово вылетают прямо от курсора, а не из угла экрана: во время
печати взгляд прикован к текущему символу и периферию не замечает.
Под суммой мельче показан её разбор - символы и множитель.

## Предметы и склад

Между узлами открывается склад: четыре случайных предмета, цены в кредитах,
перетряхивание витрины за 1 кредит. Слотов пять; когда они кончились, новый
предмет придётся менять на старый. За весь забег набегает около 42 кредитов
при полном комплекте за 26 - на рероллы остаётся немного, но остаётся. Щелчок по предмету в панели выбрасывает
его - деньги при этом не возвращаются.

| Предмет | Цена | Что делает |
|---|---|---|
| Фальстарт `x2` | 3 | Уровень начинается с множителя x2. Складывается. |
| Регистр `aA` | 5 | Заглавные можно печатать строчными. Один на забег. |
| Перебор `+++` | 6 | Каждый знак приносит на 2 символа больше. Складывается. |
| Второй шанс `2ND` | 8 | Одна ошибка засчитывается как верная буква. Откат 10 с. |

Витрина повторяема по сиду забега: один и тот же забег всегда выкладывает
один и тот же товар, поэтому раскладку можно воспроизвести при отладке.

### Как предмет показывает, что сработал

Условные предметы обязаны быть заметны в момент срабатывания, иначе игрок
не поймёт, за что заплатил.

- **Вспышка.** Слот коротко подсвечивается, вспышка гаснет за 0.7 секунды.
- **Звук.** Отдельный сигнал, не похожий ни на верную букву, ни на ошибку.
- **Откат.** Иконка становится красной, под ней идёт полоса остатка.
  За 3 секунды до готовности цвет плавно перетекает из красного в обычный
  зелёный, поэтому момент готовности виден периферийным зрением, без счёта
  секунд. В момент готовности звучит тихая подсказка.

Пассивные предметы (Перебор) не мигают вовсе: подсвечивать то, что работает
на каждой букве, значит превратить панель в мигалку.

Панель предметов стоит между показателями и текстом - боковое зрение во
время печати дотягивается туда, не уводя взгляд с курсора.

## Устройство проекта

```
src/
  core/        правила игры, чистый TypeScript без React
    balance.ts все числа игры
    typing.ts  разбор текста и распознавание нажатий
    scoring.ts формула счёта
    level.ts      состояние уровня: ввод, таймер, победа и поражение
    difficulty.ts таймер и цель узла из требуемой скорости
    run.ts        забег: выборка узлов, кредиты, инвентарь, витрина
    effects.ts система хуков, память и откаты предметов
    rng.ts     детерминированный ГСЧ по сиду
  content/     тексты и предметы как данные
    texts.ts   24 фрагмента лора, только содержание, без чисел
    items.ts   предметы: цена, иконка, текст и хуки
  state/       Zustand, мост между ядром и интерфейсом
  audio/       звуки, синтезируемые через Web Audio
  ui/          экраны и компоненты
```

Правила проекта лежат в `.claude/rules/` и подключаются из `CLAUDE.md`.
Главный инвариант: `core/` не знает про интерфейс. Предметы и боссы
добавляются как данные в `content/`, а не как новый код в ядре.

## Сложность

В меню игрок называет свою скорость печати: 30, 40, 50 или 60 слов в минуту.
Всё остальное считается от этого числа.

У каждого узла есть **требуемая скорость** - та, на которой цель добивается
к самому сигналу. Она показана рядом с таймером во время печати. Читается
буквально:

| Требуемая скорость | Что это значит |
|---|---|
| ниже твоей | есть запас на ошибки |
| равна твоей | нужна почти безошибочная игра |
| выше твоей | без предметов узел не берётся |

Кривая задана **долей** от заявленной скорости (от 0.8 до 1.5), а не
абсолютными числами. Это важно: при фиксированной кривой медленный игрок
упирался бы в стену на втором узле, а быстрый скучал бы до восьмого. Доля
ставит перелом всем на один и тот же узел - пятый из двенадцати.

Прогон на настоящем ядре, игрок заявил и печатает 40 wpm:

| Узел | Нужно | Таймер | Цель | Без предметов | Два предмета | Комплект |
|---|---|---|---|---|---|---|
| 1 | 32 | 38.0 с | 2732 | 4 ошибки | 9 | 9 |
| 4 | 40 | 34.5 с | 3296 | 1 ошибка | 7 | 9 |
| 5 | 42 | 32.5 с | 3296 | **не взять** | 7 | 9 |
| 8 | 50 | 31.5 с | 4146 | не взять | 2 | 8 |
| 10 | 55 | 30.5 с | 4572 | не взять | **не взять** | 8 |
| 12 | 60 | 30.0 с | 5088 | не взять | не взять | 5 |

Голыми руками забег доходит до четвёртого узла, на двух дешёвых предметах
до девятого, и только полный комплект доводит до конца. Это и есть смысл
магазина.

## Откуда берутся числа уровня

Тексты не содержат ни таймеров, ни целей. Узел собирается из двух чисел:

- **объём работы** - сколько знаков нужно напечатать. Растёт по ходу забега
  со 100 до 145, но не больше 70% длины текста. Хвост оставлен намеренно:
  после ошибки множитель падает и до цели приходится печатать дальше, чем
  планировалось. Без хвоста типичным поражением стало бы «текст кончился»,
  а это худшее объяснение проигрыша.
- **требуемая скорость** - она превращает объём в таймер.

Цель уровня - это счёт, который даёт чистый прогон этого объёма. Поэтому
новый фрагмент лора добавляется без всякой настройки баланса: достаточно
написать текст и дать ему номер журнала.
