# SIGNAL

Роглайт про скоростную печать, вдохновлённый Balatro.
Прототип: одно прохождение, выбор одного из трёх текстов.

## Запуск

### Что нужно

**[Node.js](https://nodejs.org/) версии 22.12 или новее** и npm 7+ (идёт в комплекте
с Node). Версия важна: Vite 8 требует Node 20.19+, а Vitest 5 уже 22.12+.
На Node постарше установка остановится с понятной ошибкой, а не сломается позже.

```bash
node -v    # должно быть v22.12.0 или выше
npm -v
```

### Первый запуск

```bash
git clone git@github.com:pol1klop1k/typing-roguelike.git
cd typing-roguelike
npm ci
npm run dev
```

Для клонированного репозитория используй именно `npm ci`, а не `npm install`.
`npm ci` ставит зависимости ровно по `package-lock.json` и предварительно
очищает `node_modules`. В этом проекте четыре пакета с нативными
бинарниками под конкретную платформу (Rolldown внутри Vite, движок
Tailwind, lightningcss и компилятор TypeScript), и `npm install` поверх
чужого состояния умеет их пропускать.

В терминале появится строка вида `Local: http://localhost:5173/`.
Открой этот адрес в браузере — игра запустится сразу, никакой сборки
и настройки не требуется.

Остановить сервер: `Ctrl + C` в терминале.

### Остальные команды

```bash
npm run test         # тесты игрового ядра, один прогон
npm run test:watch   # тесты в режиме наблюдения, перезапускаются при правках
npm run build        # production-сборка в папку dist
npm run preview      # локальный просмотр собранной версии
```

### Если что-то пошло не так

- **Порт занят.** Vite сам возьмёт следующий свободный порт и напишет его
  в терминале. Можно задать порт явно: `npm run dev -- --port 5180`.
- **`Cannot find native binding`.** Классический
  [баг npm с optional-зависимостями](https://github.com/npm/cli/issues/4828):
  платформенный бинарник не поставился. Лечится чистой переустановкой:

  ```bash
  rm -rf node_modules          # PowerShell: Remove-Item -Recurse -Force node_modules
  npm ci
  ```

  Если не помогло — удали заодно `package-lock.json` и выполни `npm install`.
  Лок-файл после этого пересоберётся, и его изменение нужно закоммитить.
- **`EBADENGINE` или отказ установки.** Версия Node ниже 22.12. Обнови Node,
  понижать требование в `package.json` не нужно.
- **Ошибки после обновления зависимостей.** Та же чистая переустановка:
  `rm -rf node_modules`, затем `npm ci`.
- **Игра не реагирует на клавиши.** Кликни один раз по странице: браузер
  не отдаёт фокус и не разрешает звук до первого действия мышью или клавишей.
- **Все нажатия идут в ошибки.** Проверь раскладку клавиатуры. Игра это
  распознаёт, не штрафует и показывает подсказку, но переключить раскладку
  нужно вручную.

## Как играть

Меню -> выбор цели -> отсчёт 3-2-1 -> печатай.

- Каждый верный знак копит **символы**.
- В конце слова символы превращаются в очки: `символы x множитель`.
- Чистое слово повышает множитель на 0.2.
- Ошибка сбрасывает множитель в x1 и отнимает время. Каждая следующая
  ошибка дороже предыдущей: 1, 2, 3, 4, 5 секунд, дальше потолок.
- Победа наступает в момент набора цели, даже если текст не дописан.
- Поражение: кончилось время либо кончился текст, а цели нет.

Ввод блокирующий: пока не нажата верная клавиша, курсор не двигается.
Backspace не нужен, ошибок в тексте не остаётся.

## Устройство проекта

```
src/
  core/        правила игры, чистый TypeScript без React
    balance.ts все числа игры
    typing.ts  разбор текста и распознавание нажатий
    scoring.ts формула счёта
    level.ts   состояние уровня: ввод, таймер, победа и поражение
    effects.ts система хуков для предметов и боссов
    rng.ts     детерминированный ГСЧ по сиду
  content/     тексты и модификаторы как данные
  state/       Zustand, мост между ядром и интерфейсом
  audio/       звуки, синтезируемые через Web Audio
  ui/          экраны и компоненты
```

Правила проекта лежат в `.claude/rules/` и подключаются из `CLAUDE.md`.
Главный инвариант: `core/` не знает про интерфейс. Предметы и боссы
добавляются как данные в `content/`, а не как новый код в ядре.

## Баланс

Числа уровней подобраны перебором по симуляции. Критерии:
чистый прогон на расчётной скорости побеждает на 55-60% текста,
оставляя 20-25% таймера в запасе, и переживает две ошибки.

| Текст | Таймер ru/en | Цель ru/en | Порог входа |
|---|---|---|---|
| Сигнал (лёгкий) | 31 / 37 с | 1500 / 2200 | ~30 wpm |
| Пробуждение (средний) | 44 / 51 с | 3700 / 5900 | ~40 wpm |
| Протокол 9 (тяжёлый) | 56 / 62 с | 8200 / 10700 | ~46 wpm |
